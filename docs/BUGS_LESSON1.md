## 🔴 Критично

### [ ] B1. Чек-лист из 10 пунктов склеивается в одну «простыню»
- **Где:** `js/lesson-data.js:1349–1369`, шаг «Страница товара и комментарии ⚠», пункт 6.
- **Симптом:** самая длинная и важная инструкция урока (регистрация двух
  пользователей + комментарии) выводится ребёнку сплошным абзацем без нумерации.
- **Причина:** пункты написаны как `1. …` / `2. …` подряд без пустых строк.
  Парсер `js/markdown.js:83` понимает списки только по `-`/`*`, а подряд идущие
  строки склеивает в один `<p>` через пробел (`js/markdown.js:42`).
- **Как чинить:** переписать в стиле остальных шагов — `**1.**` + пустая строка
  между пунктами.

### [ ] B2. Три подсказки прямо противоречат заданию
- **Где:**
  - `js/lesson-data.js:1084` — шаг «Навигация по страницам (JS-роутер)»:
    «Ничего вписывать не нужно», а пункт 3 требует заполнить **4** метки;
  - `js/lesson-data.js:1202` — шаг «Аккаунты: регистрация и вход ⚠»:
    «Вписывать метки не нужно», а пункт 2 требует **6**;
  - `js/lesson-data.js:1513` — шаг «Телефоны: бургер-меню с анимацией 📱»:
    «Вписывать ничего не нужно», а пункт 3 требует **2**.
- **Симптом:** ребёнок, открывший подсказку, пропускает метки и получает на сайте
  сырой текст `[ВПИШИ ТЕКСТ ВХОДА]` и т.п.
- **Как чинить:** переписать `hintMd` этих трёх шагов под реальные задания.

### [ ] B3. Кнопка «Вставить CSS» стоит ниже задания, которое её требует
- **Где:**
  - `js/lesson-data.js:762` — шаг «Подвал с контактами»: `[[btn:css]]` в самом
    конце, после пункта 7 с экспериментом над уже вставленным CSS. Пункт 6 говорит
    «нажми Вставить CSS ⬇», а кнопки под ним нет;
  - `js/lesson-data.js:520` — шаг «Карточки товаров + Emmet»: инструкции по
    заполнению меток идут до кнопки (мягче, но порядок тот же).
- **Причина:** кнопки размещаются ровно по месту метки `[[btn:…]]`
  (`js/lesson-render.js:180`).
- **Как чинить:** перенести `[[btn:css]]` сразу под пункт, который просит нажать кнопку.

## 🟡 Функциональные шероховатости

### [ ] B8. Заголовок баннера получается фиолетовым на оранжевом
- **Где:** правило ребёнка `h1 { color: #5b3df5; }` (шаг «Первый стиль») + сниппет
  `.banner h1 { … }` (`js/lesson-data.js:365`), который цвет не задаёт.
- **Причина:** селектор `h1` (0,0,1) применяется к элементу напрямую и бьёт
  унаследованный `.banner { color: #3a2a00 }`. Приветственную полоску спасает
  `body > h1` (0,0,2), баннер — нет.
- **Симптом:** фиолетовый заголовок на жёлто-оранжевом градиенте; нигде не оговорено,
  выглядит как случайность.
- **Как чинить:** либо добавить `color` в `.banner h1`, либо сузить правило ребёнка.

### [ ] B9. Под `file://` урок разваливается с шага «Навигация по страницам»
- **Где:** `js/lesson-data.js:790` — `localStorage.setItem("secret_flag", …)`
  в конце блока корзины.
- **Причина:** в Chrome у `file://` непрозрачный origin, `localStorage` кидает
  `SecurityError`. Весь пользовательский JS — один `<script>` (`js/preview.js:59`),
  исключение обрывает выполнение: роутер, аккаунты, страница товара и бургер-меню
  не запускаются.
- **Симптом:** урок рабочий только до шага 12 из 16 (и целиком — только в Firefox).
- **Как чинить:** обернуть обращения к `localStorage` в `try/catch` в сниппетах,
  либо явно зафиксировать в `CLAUDE.md`/README, что запуск только по HTTP.

### [ ] B10. Устаревший комментарий про `index.html`
- **Где:** `js/dev-cheat.js:12` — «Подключается ТОЛЬКО в index.html».
- **Правда:** такого файла в проекте нет, точка входа — `урок_1.html`.
